## Decision log

### 2026-09-07 — Content-addressed evidence via independent Go/Rust canonicalization, verified by cross-language agreement rather than a shared library
**Problem:** the evidence ledger's determinism claim (identical input → identical hash, in any language that will ever compute it) has to hold for two implementations that will run in different trust domains: the server-side Go ingest/ledger service, and a future browser-side Rust/WASM verifier the end user's own machine runs to independently check a verdict. If both call into one shared canonicalization library, agreement between them proves nothing except that the library agrees with itself.
**Alternatives considered:** (a) a single canonicalization implementation, exposed to Go via CGO or a subprocess, called from both sides; (b) an existing third-party CBOR library in each language, trusted to both implement RFC 8949 correctly; (c) independent, hand-written implementations of the same specified algorithm in each language, cross-checked by golden vectors.
**Chosen approach and why:** (c). A hand-written Go encoder and a hand-written Rust encoder, each implementing RFC 8949 Core Deterministic Encoding from the spec text directly, checked against each other via golden vectors neither implementation hardcodes (`ledger/golden_test.go` computes, `ledger/verify/tests/golden.rs` independently recomputes from the same fixture and asserts an exact match). Agreement between two independently-written implementations is real evidence of correctness; agreement between two callers of the same library is not.
**Technical effect produced:** BLAKE3(canonical_cbor(event)) is reproducible bit-for-bit across implementation, architecture (x86_64/arm64, CI-verified), and execution target (native/WASM) — the technical precondition for `replay --pin`'s reproducibility claim (Phase 7) and for a browser to independently re-verify a server-computed evidence hash without trusting the server's canonicalization code.
**Files touched:** `ledger/cbor.go`, `ledger/hash.go`, `ledger/merkle.go`, `ledger/verify/src/cbor.rs`, `ledger/verify/src/hash.rs`, `ledger/verify/src/merkle.rs`, `testdata/golden_events.json`.

### 2026-09-09 — The Adjudication Kernel: pure-function determinism proven across shuffle, architecture, and execution target, not asserted
**Problem:** invariant I1 (`CLAUDE.md` §2) claims `adjudicate` is a pure, total function — byte-identical output for byte-identical input, unconditionally. That claim is either backed by evidence or it's marketing copy, and it is the single fact the patent's independent claim depends on (`docs/NOVELTY-AND-PATENT.md` §1: "the decision is bit-reproducible without requiring the model to be reproducible" is the one part of this space prior art doesn't already cover).
**Alternatives considered:** (a) assert determinism from code review and unit tests of ordinary cases; (b) property-test repeated-shuffle determinism only, on one architecture; (c) prove it across every dimension a real deployment could vary: input ordering, CPU architecture, build profile, and execution target (native process vs. the WASM build a browser would actually run), plus adversarial/degenerate input via property-based fuzzing.
**Chosen approach and why:** (c). A claim this load-bearing needs the adversarial standard `agents/determinism-verifier.md` itself sets: "prefer a false alarm to a false pass." Concretely: 10,000 Fisher-Yates-shuffled re-adjudications per fixture (3 fixtures) must produce byte-identical `verdict_hash`; the identical fixed scenarios run natively on x86_64 (`ubuntu-latest`) and arm64 (`macos-latest`) and their hashes are diffed in CI, not eyeballed; the same scenarios run compiled to `wasm32-unknown-unknown` under Node's WebAssembly/BigInt integration and are compared against the native hashes for exact 64-bit equality; ~5,000 randomly generated, frequently degenerate claim sets and policies (empty strings, `i64::MIN`/`MAX` weights, unknown predicates) run through `adjudicate` wrapped in `catch_unwind`, standing in for `cargo-fuzz` (whose nightly-toolchain/libFuzzer requirements this environment couldn't verify were available).
**Technical effect produced:** the kernel's own computation matched on the first attempt, on every architecture, build profile, and execution target tested — the only defect this proof process found was in the JavaScript comparison harness itself (wasm's `i64` has no signedness; Node decodes it as signed by convention; fixed via `BigInt.asUintN(64, ...)`), documented in full in `phases/reports/PHASE-05.md` because a verification harness having its own bug, separate from the thing it's verifying, is itself worth a permanent record. Re-derivation via `replay --pin` (Phase 7) is what will turn this into the measured microseconds-vs-seconds ratio `docs/NOVELTY-AND-PATENT.md` §2 wants for the CRI 2025 technical-effect requirement; this entry is the reproducibility precondition that measurement depends on.

### 2026-09-09 — The Claim Gate enforces I2 structurally, and is proven against the real kernel, not a stand-in
**Problem:** invariant I2 (`CLAUDE.md` §2) — "no claim without evidence," "the LLM's narrative is never an input to the verdict" — is a structural claim about the system, not a behavioral hope about any particular model. The claim only has patent-relevant weight (`docs/NOVELTY-AND-PATENT.md`'s prompt-injection containment argument) if it can be shown to hold *regardless of what the model does*, including a model actively trying to defeat it, and if the proof reaches the actual deterministic kernel rather than stopping at the gate in isolation.
**Alternatives considered:** (a) unit-test the Claim Gate's rejection rules in isolation and assert the property informally; (b) test containment against a live LLM and observe whether it happens to fall for a given injection payload; (c) test containment with deterministic scripted adversarial providers that always attempt the bypass, gated by the real `ClaimGate`, adjudicated by the real kernel via `adjudicate_cli`, and assert the resulting verdict hash is byte-identical to the same investigation without the injection attempt.
**Chosen approach and why:** (c). Option (b) proves less than it appears to: a live model that happens not to fall for one specific payload today says nothing about tomorrow's payload or tomorrow's model, and a live model that *does* fall for it only proves the gate matters, not that it works. A scripted provider that deterministically always attempts the exploit is a harsher, model-independent adversary — if the gate holds against a provider engineered specifically to defeat it, every weaker (real) model's attempts are already covered. Running the full path through to a byte-identical `verdict_hash`, computed by the real Rust kernel over a subprocess bridge (`kernel/src/bin/adjudicate_cli.rs`), rather than stopping at "the gate rejected it," is what makes this a proof about the *system's verdict*, not just about one module's unit behavior.
**Technical effect produced:** two independent injection attempts (empty-evidence fabrication; plausible-but-nonexistent evidence-hash fabrication), from two independently scripted "models," both rejected with a recorded reason, and both leave the adjudicated verdict hash unchanged from the uninjected baseline — confirmed in CI against the real kernel binary on both x86_64 and arm64 (`phases/reports/PHASE-06.md`, run `34374670176`). This is the first end-to-end proof in the project connecting the non-deterministic LLM boundary to the deterministic kernel through the full real pipeline, not a mock of either side.
